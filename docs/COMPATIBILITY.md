# FDK 兼容性与验证范围

更新日期：2026-11-09。本说明整理开发过程中对两款 PC 游戏安装的只读静态检查、资源解析和导出验证结论。仓库仅发布文字说明与工具源码，不包含游戏程序、素材、资源索引、二进制证据清单或测试输出。

## 结论与适用范围

已检查的《黎之轨迹 II》和《空之轨迹 the 2nd》可以共用“资源读取 → MDL/材质解析 → glTF → FBX → Blender 预览”的主体流程。封装、压缩、MDL 版本、辅助配置和材质语义必须通过各游戏的适配层处理。同属 FDK 不代表文件格式完全相同，也不表示其他 FDK 游戏已经受支持。

本文中的《空之轨迹 the 2nd》指重制版，不是原版《空之轨迹 SC》。兼容性结论针对已验证的安装内容，不能自动推广到其他平台、发行版本、语言包组合或后续更新。

## 引擎判断依据

对已验证《空之轨迹 the 2nd》安装的可执行文件进行只读静态检查时，发现 FDK 应用标识、模型/材质/资源包管理模块的 FDK 构建路径残留、FDK 类型信息，以及 Direct3D 11/DXGI 导入。多项独立线索共同支持其使用 FDK、PC 端包含 Direct3D 11 后端的判断。

部分模块路径与《黎之轨迹 II》重合，支持共用引擎框架和模块谱系的判断，但不能证明源码、引擎版本或每个文件格式相同。构建路径残留也不表示用户电脑上存在游戏源码。第三方许可文件中出现其他引擎名称，不能单独作为整款游戏所用引擎的判断依据。

上述检查没有启动游戏、注入代码或动态跟踪加载，因此不据此声称已经确认运行时资源覆盖顺序或每个模型的实际用途。

## 输入格式差异

| 层级 | 已验证《黎之轨迹 II》 | 已验证《空之轨迹 the 2nd》 | 工具处理方式 |
|---|---|---|---|
| 资源封装 | 散文件 | FPAC v1 归档 | 统一列资源、读资源接口；归档按需读取 |
| 模型 | MDL v2 | MDL v4/v5 | 根据文件版本调用解析分支 |
| 图片 | CLE 包装后为 DDS | LZ4 frame 包装的 DDS | 先识别包装再解码，不只依据扩展名 |
| 材质配置 | 文本资产配置 | 带二进制 JSON 头的资产配置 | 分别解析并生成各游戏独立槽位表 |
| 模型辅助信息 | 散文件 `.mi` | 归档中的模型辅助信息 | 由资源读取层提供内容 |
| 下游输出 | FBX、PNG、材质与 glTF 附属记录 | 相同目录协议 | 复用 FBX 校验和 Blender 插件 |

两款游戏虽有相同名称的材质或着色器，部分槽位语义仍不同。工具按模型真实引用和当前游戏配置连接贴图；未知输入保留记录，不按名称猜测其用途。

## 历史验证覆盖

以下数字是开发阶段已完成工作的文字记录，不是仓库附带的模型数量，也不是对所有安装版本的保证。

| 验证对象 | 已完成范围 | 尚未涵盖的范围 |
|---|---|---|
| 黎之轨迹 II | 2,057 个 FBX 与共享贴图已有验证；通用后端全量续跑可复用这些结果 | 不代表所有场景、动画、着色效果或发行版本均已支持 |
| 空之轨迹 the 2nd 扫描 | 22,425 个 MDL 通过结构和材质扫描；2,149 个符合角色、装备及相关资源筛选规则 | 入选数量包含变体和相关物件，不是独立人物数；扫描成功不等于 FBX 全量验证成功 |
| 空之轨迹 the 2nd 导出 | 5 个样本完成 glTF → FBX → Blender 回读，覆盖 MDL v4/v5、角色、怪物和装备 | 其余入选模型未逐一完成 FBX 回读验证 |
| 图形界面与插件 | 游戏切换、独立扫描、所选导出、取消、材质重建与资源库隔离 | 不保证所有数据组合或未来 Blender 版本行为一致 |

Sky2 的五个样本为 `chr0001`、`chr0001_c01`、`chr5002`、`mon5000`、`equ0000`。这些仅为验证对象标识，仓库不包含对应资源。

对新游戏扫描发现的 142 个缺失贴图名称，曾在全部 46 个 PAC 索引中进行交叉查找，未找到同名源资源；涉及 1,159 条入选模型引用。工具保留缺图状态，不猜图替换，也不以缺图推断模型是否在游戏中实际使用。

## 输出与视觉边界

- 支持模型几何、骨架与蒙皮；本流程当前不导出动画轨道，不重建游戏 IK 或动态骨骼。
- Blender 的基色、法线及透明度连接用于预览，不能视为原游戏 FDK 着色器的完整复现。TOON、特殊遮罩、环境映射等输入作为参考节点和材质记录保留。
- 预览按材质开关识别阴影辅助材质，按独立 RGBA 通道加载图片，避免把打包的 Alpha 数据误用于预乘 RGB。这些修正不等于实现全部游戏着色逻辑。
- 每款游戏独立保存输出、索引、槽位语义和缓存；同名资源不跨游戏查找或重绑。

## 新增适配的要求

1. 确认目标安装及资源结构，检查封装、文件魔数、压缩和 MDL 版本。
2. 确认模型辅助信息和材质配置格式，建立独立的材质槽位语义。
3. 为目标游戏使用独立资源库，明确语言资源候选及优先规则。
4. 导出有代表性的样本，检查几何、骨架、蒙皮和贴图连接，再完成 FBX 回读。
5. 如实记录已验证版本、样本范围、缺失资源和不支持的功能。

新增支持需要代码适配与实际验证，不能只复制一条配置并修改游戏名称。最终可导出范围和成功数量，以使用者当前安装的扫描、导出及校验记录为准。
