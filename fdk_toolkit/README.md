# FDK 资源工具

这是 FDKGraphicExporter 的图形界面、导出后端和 Blender 插件源码目录。先按 [仓库安装说明](../README.md) 运行 `setup.ps1`，再双击本地生成的 `FDK_Asset_Tool.exe`。窗口打开时不会自动扫描或导出。

当前支持已验证安装版本的《黎之轨迹 II》和《空之轨迹 the 2nd》。格式与验证边界见 [兼容性说明](../docs/COMPATIBILITY.md)。本仓库不包含游戏素材、导出结果、EXE 或插件 ZIP。

## 游戏配置

本机配置文件为本目录的 `profiles.json`，初始内容来自 `profiles.example.json`。安装脚本仅在本机配置缺失时创建它。请填写自己的游戏安装路径和 Blender 4.5 可执行文件路径。图形窗口可更改游戏路径、Blender 路径和并行数，并通过「保存设置」写回配置。

| 游戏 | 适配器 | 默认输出，相对于本目录 |
|---|---|---|
| 黎之轨迹 II | `loose_cle`：散文件、CLE 包装、MDL v2 | `../kuro2_export` |
| 空之轨迹 the 2nd | `falcom_pac`：FPAC 按需读取、LZ4 图片、MDL v4/v5 | `../sky2_export` |

每款游戏使用独立资源库，模型、贴图、材质、索引和缓存均不混用。输出目录必须位于仓库内的独立子目录，与游戏安装目录分开。不要将另一款游戏的输出目录填入当前配置，也不要手工更改已有资源库的身份标记。

## 扫描与导出

1. 选择游戏配置，确认游戏目录和 Blender 4.5 路径，点击「检查环境」。
2. 首次使用或游戏更新后，点击「扫描模型目录」。该操作只建立或更新索引，不自动批量导出。
3. 搜索模型 ID 或筛选类别，勾选需要的模型。筛选变化后保留勾选；切换游戏使用各自的选择状态。
4. 选择「全部模型」或「仅导出勾选的模型」，设置并行任务数，点击「开始导出」。这里的「全部模型」指当前游戏已入选的可导出目录，不是游戏包中的全部 MDL。
5. 查看进度、日志和结果。可点击「停止任务」，之后再次执行以继续处理；「查看导出文件」打开 FBX 目录。

默认复用已完成且输入未变化的资源。「重建贴图和中间模型」用于主动重做本次范围。独立的「扫描模型目录」操作只更新目录；导出时勾选「重新扫描游戏资源」还会重建本次导出范围的中间资源。

PAC 资源先建立归档索引，再按所选模型及其真实材质引用读取所需内容，无需先把整个游戏解包到磁盘。缺失贴图会记录在报告中，不使用其他游戏或名称相似的图片替换。

## 输出内容

以下内容由用户在本地运行后生成，不随源码仓库发布：

| 位置，相对于游戏输出根目录 | 用途 |
|---|---|
| `asset_profile.json` | 资源库所属游戏与适配器标记 |
| `fbx/` | 已导出的 FBX 模型 |
| `textures/` | 由实际材质引用提取的共享 PNG 贴图 |
| `materials/`、`gltf/` | 材质记录与中间模型，供预览和校验使用 |
| `reports/model_catalog.csv` | 扫描得到的可导出模型目录 |
| `reports/shader_slots.json` | 从当前游戏配置提取的材质槽位语义 |
| `reports/texture_references.json`、`reports/texture_references.csv` | 模型、材质槽位和源贴图之间的对应关系 |
| `reports/gui_exports/时间/` | 单次导出的日志、状态和校验记录 |
| `previews/` | 插件保存的 Blender 预览工程 |

选择部分模型导出时，报告只覆盖本次范围。执行全部导出后才会更新全量 `delivery_summary.json` 和 `fbx_catalog.csv`。输出数量与成功状态以自己的运行记录为准。

## Blender 预览

安装本地构建的 `FDK_Blender_Addon.zip` 后，在插件偏好中选择本目录的 `profiles.json`，或手动选择游戏输出根目录。随后在 **3D 视图 → N → FDK** 中刷新模型列表、选择模型并导入。完整步骤见 [Blender 插件说明](BLENDER_ADDON.md)。

插件列表只显示已导出、具有 FBX 和材质记录的可预览模型。扫描索引中的其他模型需要先在导出窗口勾选并导出。切换材质模式后，对已导入模型点击「重建当前模型材质」。

角色模型保留骨架与蒙皮。当前不导出动画轨道，不重建游戏 IK、头发或布料动态，也不完整复现 FDK 着色器。基色、法线等已确认输入用于预览；特殊遮罩、TOON、环境映射等输入作为参考节点与材质记录保留。

## 维护与排查

| 现象 | 检查方法 |
|---|---|
| 找不到 Python 或转换脚本 | 保持仓库目录结构，重新运行根目录 `setup.ps1`；不要只移动 EXE |
| 找不到游戏文件 | 选择正确安装根目录，核对该发行版本是否符合已验证适配器 |
| Blender 版本检查失败 | 指向 Blender 4.5 的 `blender.exe` |
| 扫描后插件没有模型 | 先执行模型导出，再刷新插件列表 |
| 资源库身份不匹配 | 选回该游戏原资源库，或为新库使用空的独立目录 |
| 部分贴图缺失 | 查看本地引用记录与导出日志，保留缺失状态，不猜图替换 |

共用流程为：选择游戏配置 → 资源索引 → 解包装 → MDL 网格、骨架和材质解析 → 按材质引用读取贴图 → PNG/glTF → FBX → 回读校验 → Blender 预览。

新增游戏需要验证封装、MDL 版本、贴图编码和材质配置，再完成样本导出及回读检查。只复制配置并修改名称不能建立兼容性。第三方来源见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 开发测试

在仓库根目录使用安装脚本创建的 Python 环境运行普通测试：

```powershell
.\tools\python\Scripts\python.exe -m unittest discover -s fdk_toolkit/tests -p "test_*.py"
```

需要真实游戏数据的检查默认跳过；只有设置 `FDK_RUN_GAME_TESTS=1` 并准备好本机配置、游戏安装和所需资源库后才启用。Blender 集成脚本位于 `tests/integration/`，需在 Blender 环境中运行，具体前置条件见各脚本。游戏素材和生成的测试输出均不属于测试源码交付内容。
